# Receipt graph dan pemeriksaan authority sebelum aktivasi

Dokumen ini menjelaskan penghubung hasil Neo4j sealed dengan receipt PostgreSQL, operation ledger dan pemeriksaan akhir publication. Ia melanjutkan [catalog generation](graph-generation-catalog.md); receipt graph sendiri belum memenuhi kebutuhan backend indeks atau menyelesaikan Hybrid GraphRAG.

`AcknowledgePreparedGraph` melakukan write/replay dan exact readback melalui writer, mencocokkan generation/binding/hash/count dengan describe awal, lalu memanggil `GraphJobAdmission.RecordGraphReadiness`. Adapter PostgreSQL membaca ulang seluruh output dan source authority di bawah lock. Referensi output terurut wajib identik dengan catalog; receipt A tidak boleh mengesahkan checkpoint yang kini menunjuk output B. Caller adapter adalah coordinator terpercaya yang telah melakukan readback backend, bukan input HTTP receipt bebas.

Dalam satu transaksi, operation berubah dari planned ke applied, receipt backend disimpan, dan migration 0022 mencatat hash catalog, registry revision/history floor serta fingerprint source/child checkpoints. Kegagalan pada langkah mana pun membatalkan ketiganya. Lost acknowledgement dipulihkan dengan exact replay. Receipt dan catalog tetap immutable; stamp authority dapat diperbarui sesudah admission/readback baru, misalnya recovery menghasilkan checkpoint baru dengan output yang sama.

`CommitPublication` menjalankan pemeriksaan graph jika target memiliki inventory ASSEMBLE. Corpus dan snapshot terkunci sampai active-pointer CAS. Seluruh source/child jobs dikunci dengan NOWAIT untuk menghindari lock inversion dengan worker; contention menghasilkan not-ready yang dapat dicoba ulang. Registry stamp, catalog/operation hash, applied state, pembatalan, job stage/state/fence, checkpoint ID dan hash bytes harus cocok dengan authority saat receipt. Perubahan registry atau checkpoint mengharuskan admission ulang; receipt backend saja tidak cukup. Historical replay publication yang sudah published tidak mengaktifkan ulang snapshot lama.

Fingerprint membaca maksimal 512 source/child jobs dari 256 assignment, 16 MiB per checkpoint dan 64 MiB gabungan. Tidak ada network/model call di transaksi SQL. Base masih active dan membership immutable telah diperiksa saat receipt; final CAS tidak memerlukan pin receipt lama tetap hidup. Writer/receipt tetap memakai reader pin hidup. Ukur lock contention, receipt/commit p95/p99, recovery dan RSS menurut [target required](../configs/benchmark-targets.yaml); nilai belum diukur pada workload acceptance.

Carry-forward Qdrant, admission pembaca snapshot gabungan, operator graph scheduling/publication, traversal dan graph-to-answer masih harus disambungkan. Tes final CAS memakai receipt Qdrant sintetis dan trigger rollback hanya untuk mengisolasi guard graph; tidak mengklaim publikasi gabungan berhasil. Detail bukti berada di [laporan](verification-report-graph-readiness.md).
