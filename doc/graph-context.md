# Konteks dan draft bersumber dari graph

Dokumen ini menjelaskan integrasi A01 antara [bukti graph](graph-evidence.md), konteks generator, sitasi dan validasi akhir. Scope ini memungkinkan bukti graph yang sudah ditemukan dipakai untuk draft; [empat profil/fusion](graph-fusion.md) kini tersambung melalui library. Automatic seed linking, konfigurasi endpoint dan kualitas jawaban model masih pekerjaan berikutnya.

`answering.NewGraphContext` menerima hasil traversal dan pemetaan teks internal yang telah diotorisasi. Ia membuat plan immutable berisi projection path, entity, assertion, selected support, seluruh ID teks wajib dan fingerprint bukti. Kontrak Protobuf tetap C01; plan lokal ini tidak menjadi DTO API atau pengganti lease/snapshot admission. Seluruh metadata bundle, termasuk required paths, missing dependencies, completeness dan retrieval manifest, dipin. Plan dibuat **setelah** fusion/hidrasi/reranking selesai; urutan item boleh berubah, isi dan kewajiban tidak.

Projection menampilkan arah subject/predicate/object asli, label entity, qualifier/exception/temporal scope dan sumber support. JSON escaping mencegah label atau teks sumber mengubah bentuk envelope; system prompt tetap memperlakukan seluruh data sebagai untrusted. Header rendering menyatakan bahwa relasi bukan persetujuan hukum/semantik. Label dan fakta graph tidak menggantikan teks pasal.

Satu path ditempelkan pada anchor teks dengan ID terkecil, bukan diduplikasi pada semua chunk. Daftar `required_evidence_ids` tetap lengkap. `BuildContext` menghitung blok pasal beserta projection memakai tokenizer generator yang dipasok caller. Jika anchor atau satu anggota teks wajib tidak masuk, path dilaporkan omitted dan konteks menjadi PARTIAL. Path dengan coverage PARTIAL juga tetap omitted meskipun seluruh teksnya muat. Bukti yang tidak muat tidak dipotong diam-diam atau dipromosikan menjadi proof lengkap.

Pemeriksaan sebelum provider, citation mapping dan validasi sesudah provider menggunakan plan yang sama. Render text, snapshot, fingerprint evidence dan kewajiban bundle harus tepat. Menghapus required path/missing dependency, mengganti teks atau mengubah COMPLETE flag setelah plan dibuat ditolak. Tanpa plan, perilaku konservatif lama tetap berlaku: ID path saja tidak cukup. Profil GRAPH_RAG/HYBRID_GRAPH_RAG pada `EvidenceAnswerWorkflow` wajib memiliki plan; profil vector/hybrid biasa tidak menerima plan graph.

Generator hanya mengembalikan path yang source coverage-nya COMPLETE, seluruh anggota masuk konteks, dan ada satu klaim yang menyebut semua anggota teks wajib. Path disalin oleh aplikasi; model tidak memasok struktur graph. Final validator memeriksa definisi exact dan membership klaim yang sama, menolak path rekaan/duplikat serta path pada abstention. Klaim tetap UNREVIEWED dan draft tetap PARTIAL sampai evaluasi semantik terpisah membuktikan dukungannya. Cakupan byte/sumber lengkap bukan legal correctness.

Plan membatasi input evidence serta total rendering graph masing-masing 4 MiB, dan memakai aggregate traversal bound dari Q01. Batas serialized bytes bukan peak RSS; JSON escaping dapat memperbesar alokasi sementara. Membership path dipetakan sekali, fragment per anchor digabung sekali, dan membership klaim dihitung sekali per validasi. Ukur overhead projection/tokens, cakupan path setelah truncation, biaya tokenizer, p95/p99 dan peak RSS terhadap [benchmark](../configs/benchmark-targets.yaml). Angka required tidak berubah dan acceptance belum diukur.

[Verifikasi](verification-report-graph-context.md) mencakup split-support, perubahan metadata/teks/rendering, ownership plan, citation draft, dan alur Rust/PostgreSQL/Neo4j/Qdrant aktual sampai prompt graph serta sitasi. Output model dan penghitung token fixture sintetis; tes tersebut tidak membuktikan kualitas model, tokenizer parity, atau latency produksi.
