# Discovery jalur graph

Dokumen ini menjelaskan jalur discovery Q01 dari seed canonical terpin ke GraphPath bersupport. Ia menghubungkan reader Neo4j dengan algoritma retrieval Go, tanpa mengklaim bahwa kandidat tersebut sudah merupakan jawaban yang benar secara hukum.

Pemanggil memperoleh admission [graph reader](graph-read.md), menetapkan request deadline, snapshot, seed canonical dan `TraversalConfig`. `Traverse` menelusuri neighborhood secara breadth-first; satu batch memiliki paling banyak 64 frontier entity. Relasi dapat ditemukan dari subject maupun object, tetapi subject/object/predicate asli tidak diubah. Siklus dicegah per jalur sehingga dua jalur berbeda menuju entitas yang sama tetap dipertahankan. Tidak ada pemuatan seluruh graph ke heap Go.

`Reader.ReadNeighborhood` memilih ID deterministik dari gabungan adjacency fisik dan projection membership. Lookup memakai `(corpus,generation,subject)`, `(corpus,generation,object)` serta `(corpus,generation,assertion)`. Gabungan ini membuat link yang hilang tetap terdeteksi ketika record projection masih ada. Payload dibaca melalui typed reader; endpoints, seluruh support terpilih, scope/generation dan multiplicity adjacency harus sesuai. Link subject duplikat tidak boleh menggantikan link object yang hilang.

Bootstrap `EnsureSchema` memasang composite RANGE indexes, memeriksa definisinya, dan menunggu ONLINE melalui [db.awaitIndex](https://neo4j.com/docs/operations-manual/current/procedures/built-in-procedures/). Query tidak melakukan schema mutation. Generation lama memerlukan bootstrap indeks tersebut untuk performa lookup; absence index tidak mengubah correctness query menjadi permission untuk write pada request.

Budget eksplisit meliputi hop, jumlah path, jumlah assertion/support per batch dan total byte payload yang berhasil dibaca. Byte raw dihitung sebelum protobuf decode, termasuk pembacaan berulang antar-hop; Bolt framing/RSS tidak termasuk. Node count dibatasi secara tidak langsung oleh frontier/path/byte budget. Overflow assertion menghasilkan `MoreAssertions`; overflow support menggagalkan batch agar support tidak hilang diam-diam. Traversal melaporkan `assertion_budget`, `path_budget`, `hop_budget` atau `read_budget` dan tidak mengklaim frontier exhausted. Timeout/cancellation/backend integrity error menghasilkan error, bukan hasil sukses parsial yang menyembunyikan kerusakan.

Pada batas hop, status tetap konservatif jika masih ada frontier yang belum diperiksa. `FrontierExhausted` hanya true ketika seluruh frontier dalam discovery itu habis tanpa truncation. Ini bukan klaim corpus lengkap atau bahwa seluruh jalur di dunia nyata ditemukan. Batas maksimum implementasi adalah 16 hop, 4096 path, 128 assertion/256 support per batch, dan 16 MiB read; parameter run dipilih eksplisit. Angka tersebut bukan pengganti required benchmark dan belum dibuktikan sebagai operating point optimal.

Setiap GraphPath C01 mempunyai satu selected support per edge. Pemilihan support berdasarkan ID membuat hasil reproducible, bukan confidence ranking; semua alternatif tetap berada pada `TraversalResult.Supports`. Assertion utuh mempertahankan origin, qualifiers, exception refs serta temporal scope. Result memilikinya melalui clone sehingga reader yang memakai buffer ulang tidak dapat mengubah path sebelumnya.

`GraphPath.coverage` keluaran discovery tetap PARTIAL karena sumber teks, versi legal dan dependency exception belum dihidrasi. [Pemetaan bukti sumber](graph-evidence.md) kini tersedia sebagai tahap berikutnya dengan autentikasi source/version spans, temporal source filtering dan authority recheck. Dependency qualifier/exception serta applicability assertion belum lengkap; kandidat masih perlu disambungkan ke fusion/context/citation. Tidak boleh memakai discovery path langsung sebagai bukti jawaban lengkap.

Ukur fan-out, round trip, decoded/raw bytes, path coverage, latency p50/p95/p99 serta peak RSS pada snapshot/model/gold/workload terpin. Sorting dan union tetap mempunyai biaya di database; batas transfer bukan bukti batas seluruh kerja server. Target `configs/benchmark-targets.yaml` tidak berubah dan masih REQUIRED_UNMEASURED. [Laporan verifikasi](verification-report-graph-traversal.md) membedakan fixture correctness dari acceptance.
