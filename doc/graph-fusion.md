# Graph branch, fusion dan prepared query

Dokumen ini menjelaskan komposisi Q01/A01 dari seed resolver terpin, traversal dan kandidat sumber ke RRF, hidrasi, reranking, konteks serta draft. Ini library produksi dengan empat profil; baseline [exact-alias linking](query-entity-linking.md) kini tersedia, sedangkan konfigurasi graph API masih perlu disambungkan. [Laporan verifikasi](verification-report-graph-fusion.md) merekam milestone fusion awal dengan fixed seed/model fixture.

`CandidateSearch` menjalankan VECTOR_RAG melalui dense, HYBRID_RAG melalui dense+BM25, GRAPH_RAG melalui graph, dan HYBRID_GRAPH_RAG melalui ketiganya. Cabang yang diwajibkan profil harus tersedia sebelum pekerjaan dimulai. Cabang hybrid berjalan concurrent; failure membatalkan sibling, menunggu penyelesaiannya, lalu mengembalikan error. Tidak ada pergantian profil diam-diam. Budget per cabang dan total RRF tetap eksplisit dan tidak melakukan pemangkasan diam-diam.

`GraphCandidateSearch` memeriksa PostgreSQL graph admission, index/generation/snapshot, scope, lease dan request deadline. `GraphSeedResolver` menerima pertanyaan serta salinan view graph terotorisasi; ia hanya boleh membaca registry pada revision/snapshot tersebut. Ia tidak menciptakan atau menggabungkan canonical entity. `NewQueryGraphSeedResolver` kini menghasilkan laporan exact-alias linking terpin; native fixture melakukan lookup dari teks pertanyaan memakai alias sintetis. Laporan diperiksa budget/snapshot sebelum clone. Daftar kosong menghasilkan `query_seed_unresolved`, frontier tidak dianggap habis, dan bukti hilang diteruskan. GRAPH_RAG kosong menghasilkan application abstention tanpa memanggil generator; HYBRID_GRAPH_RAG tetap melaporkan ketidaklengkapan graph sambil mempertahankan bukti cabang lain.

Seed nonempty diteruskan ke reader Neo4j dan bounded traversal yang sama dengan [discovery graph](graph-traversal.md). Source lookup Qdrant mencari semua source/version/regulation pada path. Candidate rank graph saat ini adalah urutan record ID deterministik (`graph-source-id-order-v1`), bukan skor confidence, shortest-path quality, atau relevance model. RRF menyimpan provenance tiap cabang; reranker dapat menilai teks sesudah source hydration. Relevance dan kualitas ranking baseline tersebut wajib dibandingkan pada gold sebelum acceptance.

Hasil branch graph membawa owned traversal bersama hits. Sebelum cloning, seluruh entity/assertion/support, termasuk yang tidak dipakai pada path, diperiksa scope/visibility/schema dan aggregate byte bound 16 MiB. Path serta stop reasons ikut budget; stop reasons dibatasi 32 entri dan 256 byte per entri. Nil/malformed record, snapshot berbeda dan metadata graph pada cabang non-graph ditolak. Callback hidrasi menerima salinan tersendiri sehingga tidak dapat mengubah proof yang akan dipakai workflow.

Seluruh hit fusion dihidrasi sekali oleh SourceHydrator. `mergeGraphEvidence` menempelkan path/support ke teks terverifikasi dan mempertahankan semua dependency. Kandidat yang hanya berasal dari graph tetapi ternyata tidak menutup span support ditolak eksplisit sebagai `outside_graph_support_spans`. Teks dense/BM25 tetap dipertahankan walaupun di luar span graph. Mapping tidak menambah pembacaan database/model dan tidak menghapus anggota jalur berdasarkan skor. Reranker mempertahankan cardinality; [GraphContext](graph-context.md) dibuat sesudah provenance dan rerank manifest final, lalu bertanggung jawab atas token budget dan missing membership.

`RAGWorkflow.GraphAdmission` diwajibkan pada profil graph: authority diperiksa setelah hidrasi/reranking dan setelah generation sebelum hasil dikembalikan. Pin tidak boleh dilepas lebih awal. `RAGSession` menerima keempat profil, tetapi factory tetap harus mengonfigurasi dependensi yang diminta. URL sitasi berasal dari hidrasi sumber, bukan output model atau projection entity.

`PreparePublishedQuery` menerima `GraphQueryConfig` yang berisi reusable Neo4j store, seed resolver dan traversal budget. GRAPH_RAG tidak membutuhkan embedding client; Hybrid GraphRAG tetap membutuhkan dense dan lexical. Preparation membaca collection yang sudah ada, tidak membuat schema/collection. Graph-enabled prepared resources terikat pada **snapshot graph dan binding index**, sehingga graph rollover menuntut preparation baru meskipun index digunakan ulang. Bind menyalin metadata index/pin untuk mencegah mutation caller. Backend, koneksi dan model tidak dimuat ulang per query.

Bound traversal, source lookup, fusion, source hydration, graph mapping dan rendering berbeda per tahap. Mapping gabungan mempunyai hard cap 4 MiB; ini bukan peak RSS atau jaminan latency. Ukur seed coverage, fan-out, jumlah kandidat/rejection, complete-path recall, ranking sebelum/sesudah rerank, round trip, antrean dan p95/p99. Semua target [benchmark](../configs/benchmark-targets.yaml) tetap REQUIRED_UNMEASURED. Semantic query disambiguation, applicability/exception completion, gold/model evaluation, API config dan acceptance masih bagian tujuan keseluruhan.
