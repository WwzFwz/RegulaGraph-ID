# Pemakaian ulang indeks pada snapshot graph

Dokumen ini menjelaskan publikasi graph dengan generation dense/BM25 yang sudah terbit. Tujuannya menjaga snapshot query konsisten tanpa menghitung embedding ulang atau mengubah provenance dokumen. Ia melanjutkan [receipt graph](graph-readiness.md), bukan implementasi update/closure atau rebuild incremental lengkap.

`AcknowledgeIndexReuse` mengambil index binding dari parent yang di-pin, manifest target dan expected Qdrant dari publication asal. Target harus memakai corpus/generation yang sama, parent exact, sequence lebih baru dan tanpa closure. Collection, endpoint, model, statistik dan vocabulary tetap mengikuti binding asli. Source snapshot adalah snapshot build dokumen/indeks; target snapshot menentukan visibility saat query. Keduanya tidak boleh dianggap identitas yang sama.

Sebelum acknowledgement, coordinator membuka collection yang sudah ada tanpa bootstrap, membaca seluruh catalog secara keyset, memverifikasi seluruh payload dan vector terhadap Qdrant, lalu memeriksa exact count dan query probe dense/BM25 pada sequence target. Halaman dibatasi 64 record/512 KiB; satu record terlalu besar gagal eksplisit. Semua halaman harus sesuai expected count. Jalur ini tidak menyediakan operasi upsert, tidak memanggil model dan tidak mengganti pemilik generation. `VerifyInheritedServing` menerima record yang mulai terlihat sebelum target dan masih terbuka; initial writer tetap mewajibkan sequence awal exact.

`GraphJobAdmission.RecordIndexReuse` membaca ulang parent index dan authority graph di bawah lock, memeriksa origin published receipt/manifest dan semua job indeks asal, lalu menyimpan mapping immutable beserta receipt target dalam satu transaksi. Migration 0023 tidak melakukan backfill. Mapping mencatat target/parent/source snapshot, physical binding serta expected generation. Hash payload, bentuk JSON canonical dan kolom identitas diperiksa saat membaca. Receipt atau generation ID yang disalin sendiri tidak membuktikan mapping ini.

Saat aktivasi graph, `CommitPublication` memeriksa mapping, origin serta job indeks asal lagi, selain guard graph dan seluruh backend receipt. Job yang dibatalkan atau sedang berubah menggagalkan CAS. Reader target kemudian mendapat `PinnedIndex.Snapshot` baru dan `EvidenceSnapshot()` asal. SourceHydrator memverifikasi plan/document terhadap snapshot asal tetapi mengeluarkan evidence dan citation pada snapshot query. Parent historis tetap dapat dibaca di bawah lease yang sah.

Implementasi origin saat ini adalah generation awal tanpa parent/closure. Mapping dapat menyimpan parent berbeda dari source origin, tetapi pengujian integrasi saat ini mencakup satu transisi index-only ke graph+index. Registry/graph source preparation lintas beberapa publication dan incremental closures tetap pekerjaan lanjutan. Transaksi lintas backend tidak diasumsikan atomik; backend memakai namespace immutable aplikasi dan akses penulis luar berada di luar lock aplikasi.

Ukur total readback, page throughput, receipt/CAS p95/p99, lease/lock wait serta RSS pada [profil benchmark](../configs/benchmark-targets.yaml). Paging membatasi transfer per panggilan, bukan klaim performa release. Hasil backend dan batas kualitas ada di [laporan verifikasi](verification-report-index-reuse.md).
